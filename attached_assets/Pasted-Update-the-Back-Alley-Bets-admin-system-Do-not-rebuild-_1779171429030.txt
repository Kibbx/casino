TASK 2 — BANKER SIDE: GLOBAL ENABLE / DISABLE FOR PLAYER SELF-SERVICE CODES / TRANSFERS

On the Banker side, in the same area where staff already manage:

- Promo codes
- Referrals

Add a global enable/disable control for player self-service code usage and player self-service transfers.

Purpose:
If players start abusing promo codes, referral codes, or player-controlled transfers, bankers need a temporary kill switch so they can disable the system, handle the issue, and turn it back on later.

Add these settings:

promoCodesEnabled = true / false
referralCodesEnabled = true / false
playerTransfersEnabled = true / false

The Banker side should show clear controls:

Promo Codes: ENABLED / DISABLED
Referral Codes: ENABLED / DISABLED
Player Transfers: ENABLED / DISABLED

These controls should live where the existing promo/referral management already exists.

Do not create a random new page if the Banker promo/referral page already exists.

PROMO CODES DISABLED BEHAVIOR:

When promoCodesEnabled is false:

- Players cannot redeem promo codes themselves
- Promo code fields should be disabled or hidden from player-facing screens
- Backend must reject promo code redemption
- Existing promo codes are not deleted
- Promo history is not deleted
- Staff can still view/manage existing promo codes
- Player should see:
  “Promo codes are temporarily disabled.”

When promoCodesEnabled is true:

- Promo codes work normally again

REFERRAL CODES DISABLED BEHAVIOR:

When referralCodesEnabled is false:

- Players cannot submit/use referral codes themselves
- Referral fields should be disabled or hidden from player-facing screens
- Backend must reject referral code claims
- Existing referral codes are not deleted
- Referral history is not deleted
- Staff can still view/manage referral data
- Player should see:
  “Referral codes are temporarily disabled.”

When referralCodesEnabled is true:

- Referral codes work normally again

PLAYER TRANSFERS DISABLED BEHAVIOR:

When playerTransfersEnabled is false:

- Players cannot use self-service transfers
- Transfer UI should be disabled or hidden from player-facing screens
- Backend must reject player-initiated transfers
- Existing transfer history is not deleted
- Staff/banker/admin manual transfers should still work if they already exist
- Player should see:
  “Player transfers are temporarily disabled.”

When playerTransfersEnabled is true:

- Player self-service transfers work normally again

IMPORTANT BACKEND RULE:

These toggles must be enforced backend-side.

Do not only hide buttons on the frontend.

Players must not be able to bypass disabled systems by calling API endpoints directly.

Before applying promo reward:

if promoCodesEnabled === false:
  reject request
  return "Promo codes are temporarily disabled."

Before applying referral reward:

if referralCodesEnabled === false:
  reject request
  return "Referral codes are temporarily disabled."

Before allowing player self-transfer:

if playerTransfersEnabled === false:
  reject request
  return "Player transfers are temporarily disabled."

These checks must happen before:
- crediting chips
- marking code as used
- creating reward history
- moving balance
- completing transfer
- updating player stats
