Fix the password-protected game access bug.

Current issue:
When a game has a password set, clicking the game does not tell the user that a password is required. It immediately sends them into the lobby/game instead.

Expected behavior:

If a game has no password and is open, clicking it should work normally.
If a game has a password set, clicking it should show a password prompt/modal before entering.
The user should only be sent to the lobby/game after entering the correct password.
If the password is wrong, show an error and keep them on the password prompt.
Do not expose the actual password to the frontend.
The frontend should only receive a safe flag like hasPassword: true.

Please inspect and reuse the existing password system instead of rebuilding it.

Investigate:

Existing backend game password fields/check logic
Existing API route for validating game passwords
Existing frontend game card click handler
Existing password modal or password entry component
Whether frontend is receiving hasPassword, passwordProtected, requiresPassword, or another field
Whether the click handler ignores the password flag
Whether navigation happens before password validation
Whether production API responses differ from Replit

Fix:

Make the game list/card API return a safe password-protected flag.
Update the game card click handler to check that flag before navigating.
If password is required, open the password prompt instead of routing to the lobby.
Validate the entered password through the backend.
Only navigate after successful backend validation.
Make sure disabled/closed games still cannot be entered even with a password.
Keep password-protected and closed-state logic separate but compatible.

Add safe debug logs for:

clicked game ID/name
whether frontend thinks the game has a password
whether password modal opens
password validation route hit
validation success/failure

Do not log the actual password value.

Expected result:
Password-protected games clearly show that they require a password, prompt the user before entry, validate correctly, and only allow lobby/game access after the correct password is entered.
