Fix locked/password-protected game status consistency across all game sections.

Current issue:
When a game is locked/password-protected on the Table Games page, it does not appear locked on the Recently Played or Live Activity sections. Those sections still make the game look open/unlocked.

Expected behavior:
If a game is locked anywhere, it must show locked everywhere:

* Table Games
* Recently Played
* Live Activity
* Home page game cards
* Search results
* Any shared game carousel/list

### Requirements

1. Use one backend source of truth.

   * The backend should return a safe password flag for every game, such as:

     * `hasPassword: true`
     * `isLocked: true`
     * or `requiresPassword: true`
   * Do not expose the actual password to the frontend.

2. Make all sections use the same lock field.

   * Table Games should not be the only page reading password state.
   * Recently Played and Live Activity must use the same locked/password flag.
   * Remove hardcoded `OPEN` or unlocked states that override backend data.

3. Update shared GameCard behavior.

   * If a game is locked, show a lock icon/badge.
   * Button can still say `Join Table` or `Play Now`, but clicking it must open the password modal first.
   * Do not navigate directly into the lobby/game until password validation succeeds.

4. Keep closed and locked separate.

   * Closed game:

     * show `CLOSED`
     * dim/fade card
     * disable click
   * Locked but open game:

     * show locked badge/icon
     * allow click only to password prompt
     * enter only after correct password

5. Backend enforcement.

   * Even if a user enters from Recently Played, Live Activity, or a direct URL, the backend must still require password validation.
   * Do not trust only frontend checks.

6. Refresh and cache.

   * Make sure Recently Played and Live Activity refresh game status from backend.
   * Clear or update stale local/cache data after admin changes password settings.
   * Ensure production and Replit use the same response fields.

Expected result:
A locked game appears locked everywhere, opens the password modal from every section, and never allows direct entry without the correct password.
